### 72B 느린 이유 — 물리적 대역폭 한계

```

  실측: 1.2 tok/s ← 이론치와 근접, 소프트웨어 문제 아님
```

**결론: 72B Q4_K_M은 이 하드웨어에서 최대 1.2 tok/s. 이건 물리 법칙이다.**

| Whisper large-v3 | ~3GB | Scheduler 세션 사용 |
| 8B 모델 (로드 시) | ~5GB | 하나씩 스왑 |

### 충돌 시나리오

```
✅ 14B + Whisper 동시 사용 시:  ★★★ 최적!
  17.8GB (14B) + 3GB (Whisper) + 1.5GB (OS) = 22.3GB < 24GB ← VRAM 안에 들어감!
  → 14B 82 tok/s + Whisper 13x 실시간 동시 사용 가능!

✅ 14B + 8B 동시 사용 시:
  17.8GB + 5GB + 1.5GB = 24.3GB ≈ 24GB ← 아슬아슬하지만 가능할 수도
  → Ollama 자동 관리로 테스트 필요

⚠️ 32B + Whisper 동시 사용 시:
  22.2GB (32B) + 3GB (Whisper) + 1.5GB (OS) = 26.7GB > 24GB ← VRAM 초과!
  → 32B의 GPU 적재율 감소 → 속도 저하 예상

⚠️ 32B + 8B 동시 사용 시:
  22.2GB + 5GB + 1.5GB = 28.7GB > 24GB ← VRAM 초과!
  → Ollama가 둘 중 하나를 자동 언로드

⚠️ 72B + Whisper 동시 사용 시:
  16.9GB (72B) + 3GB (Whisper) + 1.5GB (OS) = 21.4GB < 24GB ← 이론상 가능

⚠️ 72B + Whisper + 8B 동시 사용 시:
  16.9GB + 3GB + 5GB + 1.5GB = 26.4GB > 24GB ← VRAM 초과!
```

**핵심 발견: 14B가 Whisper와 동시 사용 가능한 유일한 고품질 모델!**
- 14B (17.8GB) + Whisper (3GB) + OS (1.5GB) = 22.3GB — VRAM 1.7GB 여유
- 32B/72B는 Whisper와 동시 사용 불가하거나 아슬아슬
- **Jarvis 시스템의 "음성 입력 → 14B 처리 → 음성 출력" 파이프라인 실현 가능!**
